    Beginner

    Frontend installeren

    Voordat je de Zabbix frontend configureert, moet je ervoor zorgen dat het systeem voldoet aan de vereisten en is voorbereid zoals beschreven in het vorige hoofdstuk: Aan de slag. Deze server kan dezelfde zijn waarop eerder de Zabbix serverpakketten zijn geïnstalleerd, of het kan een aparte machine zijn.

    Voer alle volgende stappen uit op de server die is aangewezen voor de frontend.

    Frontend installeren met NGINX

    Frontend-pakketten installeren

    Red Hat 

    # List all available PHP modules and enable PHP 8.2
dnf module list php -y
dnf module enable php:8.2
# When using MySQL/MariaDB
dnf install zabbix-nginx-conf zabbix-web-mysql
# or when using PostgreSQL
dnf install zabbix-nginx-conf zabbix-web-pgsql
    SUSE 
    # When using MySQL/MariaDB
zypper install zabbix-nginx-conf zabbix-web-mysql php8-openssl php8-xmlreader php8-xmlwriter
# or when using PostgreSQL
zypper install zabbix-nginx-conf zabbix-web-pgsql php8-openssl php8-xmlreader php8-xmlwriter

    SUSE Linux Enterprise Server

    Zorg er op SUSE Linux Enterprise Server (SLES) voor dat je geabonneerd bent op de repository "SUSE Linux Enterprise Module Web and Scripting". Die biedt toegang tot de PHP 8-pakketten die nodig zijn voor de installatie van de Zabbix frontend. Op SLES-versies ouder dan 16 gebruik je SUSEConnect in plaats van suseconnect.

    suseconnect -p sle-module-web-scripting/16/x86_64
    De URL van de Web and Scripting-module kan per servicepack verschillen. Gebruik het volgende commando om de juiste module te vinden. 
    suseconnect --list-extensions

    Ubuntu 

    # When using MySQL/MariaDB
sudo apt install zabbix-frontend-php php8.3-mysql zabbix-nginx-conf
# or when using PostgreSQL
sudo apt install zabbix-frontend-php php8.3-pgsql zabbix-nginx-conf

    Deze commando's installeren de Zabbix frontend-pakketten en de benodigde afhankelijkheden voor NGINX.

    Vanaf SUSE 16 is SELinux de standaardbeveiligingsmodule in plaats van AppArmor. Standaard kan SELinux op SUSE verhinderen dat PHP-FPM uitvoerbaar geheugen toewijst voor PHP JIT-compilatie, verbinding maakt met de Zabbix server of via TCP verbinding maakt met de databaseserver. Sta deze acties toe met:

    SELinux: benodigde rechten voor PHP-FPM inschakelen

    setsebool -P httpd_execmem 1
setsebool -P httpd_can_connect_zabbix 1
setsebool -P httpd_can_network_connect_db 1
    Tip

    Installeer bij SELinux-problemen bij voorkeur het pakket setroubleshoot. Dit registreert SELinux-weigeringen in het systeemlog en geeft suggesties om de problemen op te lossen.

    Afhankelijk van de standaardinstellingen van je Linux-distributie kan systemd verhinderen dat PHP-FPM naar de directory /etc/zabbix/web schrijft. Die schrijftoegang is nodig tijdens de installatie van de Zabbix frontend. Maak daarom een drop-in-bestand aan om dit toe te staan:

    Systemd: PHP-FPM toestaan te schrijven naar /etc/zabbix/web

    systemctl edit php-fpm

    Hiermee open je een editor om het drop-in-bestand /etc/systemd/system/php-fpm.service.d/override.conf aan te maken. Dit bestand vult de bestaande serviceconfiguratie aan of overschrijft onderdelen ervan.

    Voeg de volgende regels toe:

    [Service]
ReadWritePaths=/etc/zabbix/web

    Sluit daarna de editor en laad de systemd-configuratie opnieuw:

    systemctl daemon-reload
    Hoe verhindert systemd dat PHP-FPM naar /etc/zabbix/web schrijft?

    Op veel moderne Linux-distributies gebruikt systemd sandboxing om de rechten van services te beperken. Zo krijgen services alleen toegang tot de middelen die ze nodig hebben. PHP-FPM kan daardoor standaard geen schrijfrechten hebben op bepaalde directories, waaronder /etc/zabbix/web. De systemd-directives ProtectSystem en ReadWritePaths regelen deze toegang.

    Tip

    Schrijftoegang tot /etc/zabbix/web is normaal alleen nodig tijdens de eerste installatie van de Zabbix frontend. Na de installatie kun je het drop-in-bestand verwijderen om de beveiliging verder aan te scherpen.

    Eerst passen we de NGINX-configuratie aan, zodat de standaardconfiguratie niet langer poort 80 gebruikt en de Zabbix frontend die poort kan overnemen.

    NGINX-configuratie aanpassen op Red Hat

    vi /etc/nginx/nginx.conf

    Op Ubuntu hoef je nginx.conf niet aan te passen. Voer daar alleen sudo unlink /etc/nginx/sites-enabled/default uit.

    Zoek in dit configuratiebestand het blok dat begint met server {:

    Oorspronkelijke configuratie

    server {
    listen 80;
    listen [::]:80;
    server_name *;
...
    Tip

    Dit blok kan verschillen naargelang je distributie en NGINX-versie.

    Zet vervolgens de listen- en server_name-directives in commentaar om de standaard HTTP-serverconfiguratie uit te schakelen. Plaats daarvoor een # aan het begin van de regels, zoals hieronder:

    Configuratie na aanpassing

    server {
    #listen 80;
    #listen [::]:80;
    #server_name *;
...

    Pas nu het NGINX-configuratiebestand van Zabbix aan, zodat de frontend poort 80 gebruikt. Open het volgende bestand:

    Zabbix-configuratie voor NGINX aanpassen

    sudo vi /etc/nginx/conf.d/zabbix.conf

    Pas de volgende regels aan:

    Oorspronkelijke configuratie

    server {
#       listen          8080;
#       server_name     example.com;

        root    /usr/share/zabbix;

        index   index.php;
...

    Verwijder de # voor de eerste twee regels en vul de juiste poort en domeinnaam voor je Zabbix frontend in.

    Tip

    Als je geen domeinnaam hebt, kun je voor server_name de waarde _ gebruiken, zoals in het voorbeeld hieronder:

    Configuratie na aanpassing

    server {
        listen          80;
        server_name     _;

         root    /usr/share/zabbix;

         index   index.php;

    De webserver en PHP-FPM zijn nu klaar om te starten. Met de volgende commando's schakel je de services in en start je ze meteen:

    Frontend-services inschakelen en starten

    Red Hat / SUSE 

    systemctl enable nginx php-fpm --now

    Ubuntu 

    sudo systemctl enable nginx php8.3-fpm --now

    Controleer of de service correct draait en automatisch wordt gestart na een reboot.

    Controleren of de service draait

    sudo systemctl status nginx
    Voorbeelduitvoer

    Nu de service draait en automatisch opstart, moeten we nog inkomend HTTP-verkeer toestaan in de firewall. Voer de volgende commando's uit:

    Firewall configureren

    Red Hat / SUSE 

    firewall-cmd --add-service=http --permanent
firewall-cmd --reload

    Ubuntu 

    sudo ufw allow 80/tcp

    Open je browser en ga naar de URL of het IP-adres van je Zabbix frontend:

    Frontend-configuratie

    http://<ip or dns of the zabbix frontend server>/

    Als alles correct is ingesteld, verschijnt de welkomstpagina van Zabbix. Bij fouten controleer je de configuratie en het NGINX-logbestand /var/log/nginx/error.log, of voer je het volgende commando uit:

    journalctl -xeu nginx

    Dit helpt je de oorzaak van eventuele fouten te achterhalen.

    1.3 Taalkeuze op de Zabbix-welkomstpagina

    Wil je bijvoorbeeld Chinees of een andere taal installeren? Gebruik het volgende commando om de beschikbare locales van je besturingssysteem te bekijken.

    Taalpakketten installeren

    Red Hat 

    dnf list glibc-langpack-*

    SUSE 

    localectl list-locales

    Ubuntu 

    apt-cache search language-pack

    Op Ubuntu kun je de volgende foutmelding tegenkomen: ocale for language "en_US" is not found on the web server.

    Dit kun je oplossen met de volgende commando’s.

    sudo locale-gen en_US.UTF-8
sudo update-locale
sudo systemctl restart nginx php8.3-fpm

    Locale-pakket installeren

    Red Hat 

    dnf install glibc-langpack-zh.x86_64
sudo systemctl restart nginx php-fpm

    SUSE 

    zypper install glibc-locale
sudo systemctl restart nginx php-fpm

    Ubuntu 

    sudo apt install language-pack-zh-hans
sudo systemctl restart nginx php8.3-fpm

    Wanneer je terugkeert naar de Zabbix frontend en de pagina opnieuw laadt, kun je Chinees als taal selecteren.

    1.4 Taal selecteren in Zabbix

    Note

    Als je voorkeurstaal niet beschikbaar is in de Zabbix frontend, is de vertaling mogelijk nog onvolledig of niet beschikbaar. Zabbix is een opensourceproject waarvan de vertalingen door de community worden onderhouden. Je kunt zelf bijdragen aan de vertaling.

    Bezoek https://translate.zabbix.com/ om mee te helpen vertalen. Zodra je vertaling klaar en beoordeeld is, wordt die opgenomen in een volgende kleine patchversie van Zabbix. Zo help je Zabbix voor meer gebruikers toegankelijk te maken.

    Selecteer de gewenste taal en klik op Next. Op het volgende scherm controleert Zabbix of aan alle vereisten is voldaan. Los eventuele problemen eerst op. Als alles in orde is, klik je opnieuw op Next.

    1.5 Vereisten voor Zabbix

    Op de volgende pagina configureer je de databaseverbinding:

    1. Select the Database Type: Kies MySQL of PostgreSQL, afhankelijk van je installatie.
    2. Enter the Database Host: Vul het IP-adres of de DNS-naam van je databaseserver in. Gebruik poort 3306 voor MariaDB/MySQL of 5432 voor PostgreSQL.
    3. Enter the Database Name: Vul de databasenaam in. In ons voorbeeld is dat zabbix.
    4. Enter the Database Schema: Alleen voor PostgreSQL. Vul de schemanaam in die je voor de Zabbix server hebt aangemaakt. In ons voorbeeld is dat zabbix_server.
    5. Enter the Database User: Vul de databasegebruiker voor de Zabbix frontend in. In de basisinstallatie hebben we twee gebruikers aangemaakt: zabbix-web voor de frontend en zabbix-srv voor de Zabbix server. Gebruik hier dus zabbix-web en vul het bijbehorende wachtwoord in.

    Zorg ervoor dat de optie Database TLS encryption niet is geselecteerd en klik op Next step om verder te gaan.

    1.6 Databaseverbinding van Zabbix

    De installatie is bijna voltooid. Stel nog de volgende opties in:

    1. Assigning an Instance Name: Kies een duidelijke naam voor je Zabbix instance.
    2. Selecting the Timezone: Kies de tijdzone van je locatie of de tijdzone die je in de Zabbix frontend wilt gebruiken.
    3. Setting the Default Time Format: Selecteer het gewenste standaardtijdformaat.
    4. Encrypt connections from Web interface: In de schermafbeelding heb ik dit aangevinkt, maar doe dat hier nog niet. Deze optie heeft betrekking op de versleuteling van de communicatie tussen de Zabbix frontend en je browser. We behandelen dit later.

    Daarna kun je de installatie afronden.

    Note

    Het is aan te raden om voor je Zabbix server de tijdzone UTC te gebruiken, vooral wanneer je systemen in meerdere tijdzones beheert. UTC zorgt voor consistentie bij tijdsafhankelijke acties en events.

    1.7 Overzicht van de Zabbix-instellingen

    Klik opnieuw op Next step. Je krijgt nu een bevestiging dat de configuratie is geslaagd. Klik op Finish om de installatie af te ronden.

    1.8 Zabbix-installatie voltooid

    Je kunt nu inloggen:

    1.9 Inloggen bij Zabbix

    • Gebruikersnaam: Admin
    • Wachtwoord: zabbix

    Hiermee is de installatie van de Zabbix frontend afgerond. Wil je de frontend verder beveiligen? Lees dan ook het hoofdstuk Securing Zabbix voor aanvullende richtlijnen en best practices.

    Tip

    Kun je de configuratie aan het einde niet opslaan? Controleer dan of je de SELinux-instructies hebt uitgevoerd of SELinux hebt uitgeschakeld. Controleer ook of de webservergebruiker (meestal wwwrun of www) schrijfrechten heeft op /etc/zabbix/web.

    Conclusie

    Met de installatie en configuratie van de Zabbix frontend heb je nu ook de gebruikersinterface van je Zabbix-monitoringomgeving ingericht. We hebben de benodigde pakketten geïnstalleerd, de webserver en PHP geconfigureerd, de databaseverbinding ingesteld en de frontend-instellingen aangepast.

    Je Zabbix instance is nu operationeel en vormt de basis voor verdere monitoring en alerting. In de volgende hoofdstukken gaan we dieper in op het afstemmen van Zabbix, het optimaliseren van de prestaties en belangrijke functies die Zabbix tot een krachtig observability-platform maken.

    Nu je Zabbix-omgeving draait, kunnen we verder met de volgende stappen.
