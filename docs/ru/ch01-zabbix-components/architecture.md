# Архитектура Zabbix

В этой главе мы рассмотрим процесс установки сервера Zabbix. Существует множество различных
способов настройки сервера Zabbix. Мы рассмотрим наиболее распространённые
варианты с использованием MariaDB и PostgreSQL на базовых дистрибутивах RHEL, SLES и Ubuntu.

Перед началом установки важно понять архитектуру Zabbix.
Сервер Zabbix структурирован в модульном формате и состоит из трёх основных компонентов,
которые мы подробно рассмотрим.

- Сервер Zabbix
- Веб-сервер Zabbix
- База данных Zabbix

!!! abstract "Создание пользователей базы данных"

    В нашей конфигурации мы создадим двух пользователей базы данных `zabbix-web` и `zabbix-srv`.
    Пользователь zabbix-web будет использоваться для подключения фронтенда к базе данных Zabbix.
    Пользователь zabbix-srv будет использоваться сервером Zabbix для подключения к базе данных.
    Это позволяет ограничить права доступа каждого пользователя только необходимыми.

_1.1 Основная
распределённая установка_

Все эти компоненты могут быть установлены на одном сервере или распределены
по трём отдельным серверам. Ядром системы является сервер Zabbix, часто называемый "мозгом".
Этот компонент отвечает за обработку вычислений триггеров и отправку уведомлений.
База данных служит хранилищем для конфигурации сервера Zabbix и всех собранных им данных.
Веб-сервер предоставляет пользовательский интерфейс (фронтенд) для взаимодействия с системой.
Важно отметить, что API Zabbix является частью компонента фронтенда, а не сервера Zabbix.

Эти компоненты должны работать вместе без проблем, как показано на диаграмме выше.
Сервер Zabbix должен читать конфигурации и хранить данные мониторинга в базе данных,
в то время как фронтенд нуждается в доступе для чтения и записи конфигурационных данных.
Кроме того, фронтенду необходимо проверять состояние сервера Zabbix и получать дополнительную
необходимую информацию для обеспечения бесперебойной работы.

Для нашей установки мы будем использовать два виртуальных машины (VM): одна VM будет
включать как сервер Zabbix, так и фронтенд Zabbix, а вторая VM будет содержать базу данных Zabbix.

???+ note

    Возможно установить все компоненты на одной VM или каждый компонент на отдельной VM.
    Причина разделения базы данных в нашем примере заключается в том, что база данных
    вероятно будет первой частью системы, которая вызовет проблемы с производительностью.
    Это также компонент, который требует дополнительного внимания при его отделении от других
    компонентов, поэтому мы выбрали разделить базу данных в этом примере.

Мы рассмотрим следующие темы:

- Установка нашей базы данных на основе MariaDB.
- Установка нашей базы данных на основе PostgreSQL.
- Установка сервера Zabbix.
- Установка фронтенда.
