    Iniciante

    Instalando o frontend

    Antes de configurar o frontend do Zabbix, certifique-se de que o sistema atende aos requisitos e está preparado conforme descrito no capítulo anterior: Início rápido. Este servidor pode ser o mesmo onde os pacotes do Zabbix server foram instalados anteriormente, ou pode ser uma máquina separada.

    Execute todas as etapas subsequentes no servidor designado para o frontend.

    Instalando o frontend com NGINX

    instalar pacotes de frontend

    Red Hat 

    # List all available php modules and active php-8.2
dnf module list php -y
dnf module enable php:8.2
# When using MySQL/MariaDB
dnf install zabbix-nginx-conf zabbix-web-mysql
# or when using PostgreSQL
dnf install zabbix-nginx-conf zabbix-web-pgsql

    SUSE 

    # When using MySQL/MariaDB
zypper install zabbix-nginx-conf zabbix-web-mysql php8-openssl php8-xmlreader php8-xmlwriter
# or when using PostgreSQL
zypper install zabbix-nginx-conf zabbix-web-pgsql php8-openssl php8-xmlreader php8-xmlwriter

    Suse Linux Enterprise Server

    No SUSE Linux Enterprise Server (SLES), certifique-se de que você está inscrito no repositório "SUSE Linux Enterprise Module Web and Scripting" para acessar os pacotes PHP 8 necessários para a instalação do frontend do Zabbix: (em versões do SLES < 16, o comando é "SUSEConnect" em vez de "suseconnect")

    suseconnect -p sle-module-web-scripting/16/x86_64

    A URL real para o módulo de web scripting pode ser diferente dependendo do pacote específico. Use o seguinte comando para determinar a correta. 

    suseconnect --list-extensions

    Ubuntu 

    # When using MySQL/MariaDB
sudo apt install zabbix-frontend-php php8.3-mysql zabbix-nginx-conf
# or when using PostgreSQL
sudo apt install zabbix-frontend-php php8.3-pgsql zabbix-nginx-conf

    Este comando instalará os pacotes de frontend junto com as dependências necessárias para NGINX.

    A partir do SUSE 16, SELinux é o módulo de segurança padrão em vez de AppArmor. Por padrão, PHP-FPM não está permitido pelo SELinux no SUSE para - mapear memória exec necessária para a compilação JIT do PHP, - conectar ao servidor Zabbix ou - se conectar ao servidor de banco de dados por TCP. Precisamos informar o SELinux para permitir tudo isso:

    SELinux: Permitir que PHP-FPM mapeie memória exec

    setsebool -P httpd_execmem 1
setsebool -P httpd_can_connect_zabbix 1
setsebool -P httpd_can_network_connect_db 1
    Tip

    Para solucionar problemas relacionados ao SELinux, é recomendado instalar o pacote setroubleshoot, que registra quaisquer negações do SELinux no log do sistema e fornece sugestões sobre como resolvê-las.

    Dependendo das configurações padrão da sua distribuição Linux, PHP-FPM pode não ser permitido pelo Systemd para escrever no diretório /etc/zabbix/web necessário para a configuração do frontend do Zabbix. Para habilitar isso precisamos criar um arquivo drop-in:

    Systemd: Permitir que PHP-FPM escreva em /etc/zabbix/web

    systemctl edit php-fpm

    Isso abrirá um editor para criar o arquivo drop-in /etc/systemd/system/php-fpm.service.d/override.conf que substituirá ou estenderá o arquivo de serviço existente.

    Adicione as seguintes linhas ao arquivo:

    [Service]
ReadWritePaths=/etc/zabbix/web

    Em seguida, saia do editor e recarregue a configuração do Systemd:

    systemctl daemon-reload
    Como o Systemd está impedindo PHP-FPM de escrever em /etc/zabbix/web?

    Em muitas distribuições Linux modernas, o Systemd emprega uma característica de segurança conhecida como sandboxing para limitar as capacidades dos serviços. Isso é feito para aumentar a segurança ao limitar o acesso dos serviços apenas aos recursos que eles precisam para funcionar. Por padrão, PHP-FPM pode ser restrito de escrever em certos diretórios, incluindo /etc/zabbix/web, para prevenir potenciais vulnerabilidades de segurança. Isso é imposto através das diretrizes do Systemd ProtectSystem e ReadWritePaths, que controlam o acesso ao sistema de arquivos dos serviços.

    Tip

    Normalmente, a permissão para escrever em /etc/zabbix/web é necessária apenas durante a configuração inicial do frontend do Zabbix. Após a conclusão da configuração, você pode remover o arquivo drop-in novamente para fortalecer ainda mais a segurança do seu sistema.

    A primeira coisa que precisamos fazer é alterar o arquivo de configuração do NGINX para que não usemos a configuração padrão e sirvamos o frontend do Zabbix na porta 80.

    Editar configuração do nginx para Red Hat

    vi /etc/nginx/nginx.conf

    Se você estiver no Ubuntu, não é necessário editar nginx.conf; basta executar sudo unlink /etc/nginx/sites-enabled/default

    Neste arquivo de configuração procure pelo bloco que começa com server {:

    Configuração original

    server {
    listen 80;
    listen [::]:80;
    server_name *;
...
    Tip

    Este bloco pode ser diferente dependendo da sua distribuição e versão do NGINX.

    Em seguida, comente as diretrizes listen e server_name para desativar a configuração padrão do servidor HTTP. Você pode fazer isso adicionando um # no início de cada linha, como no exemplo abaixo:

    Configuração após edição

    server {
    #listen 80;
    #listen [::]:80;
    #server_name *;
...

    O arquivo de configuração do Zabbix agora deve ser modificado para assumir o serviço padrão na porta 80 que acabamos de desativar. Abra o seguinte arquivo para edição:

    Editar a configuração do Zabbix para nginx

    sudo vi /etc/nginx/conf.d/zabbix.conf

    E altere as seguintes linhas:

    Configuração original

    server {
#       listen          8080;
#       server_name     example.com;

        root    /usr/share/zabbix;

        index   index.php;
...

    Remova o # na frente das duas primeiras linhas e modifique-as com a porta e domínio corretos para seu frontend.

    Tip

    Se você não tiver um domínio, pode substituir servername por _ como no exemplo abaixo:

    Configuração após a edição

    server {
        listen          80;
        server_name     _;

         root    /usr/share/zabbix;

         index   index.php;

    O servidor web e o serviço PHP-FPM agora estão prontos para ativação e inicialização persistente. Execute os seguintes comandos para habilitar e iniciar imediatamente:

    Reiniciar os serviços do frontend

    Red Hat / SUSE 

    systemctl enable nginx php-fpm --now

    Ubuntu 

    sudo systemctl enable nginx php8.3-fpm --now

    Vamos verificar se o serviço está em execução corretamente e habilitado para que sobreviva ao nosso próximo reinício.

    Verificar se o serviço está rodando

    sudo systemctl status nginx
    Saída de exemplo

    Com o serviço em operação e configurado para inicialização automática, a última etapa preparatória envolve ajustar o firewall para permitir tráfego HTTP entrante. Execute os seguintes comandos:

    Configurar o firewall

    Red Hat / SUSE 

    firewall-cmd --add-service=http --permanent
firewall-cmd --reload

    Ubuntu 

    sudo ufw allow 80/tcp

    Abra seu navegador e acesse a URL ou IP do seu frontend :

    Configuração do frontend

    http://<ip or dns of the zabbix frontend server>/

    Se tudo correr bem, você deve ser recebido por uma página de boas-vindas do Zabbix. Em caso de erro, verifique a configuração novamente ou examine o arquivo de log do NGINX /var/log/nginx/error.log ou execute o seguinte comando:

    journalctl -xeu nginx

    Isso deve ajudá-lo a localizar os erros que cometeu.

    Escolha o local de idioma apropriado

    O locale en_US usa a notação de data americana e um relógio de 12 horas, enquanto en_GB usa uma notação de data internacional e um relógio de 24 horas.

    O frontend do Zabbix apresenta um conjunto limitado de localizações disponíveis, como mostrado.

    1.3 Escolha da linguagem no boas-vindas do Zabbix

    E se quisermos instalar o chinês ou outra língua da lista? Execute o próximo comando para obter uma lista de todos os locais disponíveis para seu SO.

    Instalar pacotes de idioma

    Red Hat 

    dnf list glibc-langpack-*

    SUSE 

    localectl list-locales

    Ubuntu 

    apt-cache search language-pack

    Usuários do Ubuntu provavelmente notarão o seguinte erro Locale for language "en_US" is not found on the web server."

    Isso pode ser resolvido facilmente com os seguintes comandos.

    sudo locale-gen en_US.UTF-8
sudo update-locale
sudo systemctl restart nginx php8.3-fpm

    Red Hat

    Ubuntu 

    sudo apt-cache search language-pack | grep -i zh

    Em RedHat e Ubuntu, o comando retorna duas linhas; no entanto, dado o código de idioma identificado, 'zh_CN', apenas o primeiro pacote precisa ser instalado. no SUSE ou os locais C.UTF-8 e en_US.UTF-8 são instalados ou todos os locais disponíveis são instalados, dependendo de se o pacote glibc-locale está instalado ou não.

    Instalar o pacote do locale

    Red Hat 

    dnf install glibc-langpack-zh.x86_64
sudo systemctl restart nginx php-fpm

    SUSE 

    zypper install glibc-locale
sudo systemctl restart nginx php-fpm

    Ubuntu 

    sudo apt install language-pack-zh-hans
sudo systemctl restart nginx php8.3-fpm

    Ao retornar agora ao nosso frontend, somos capazes de selecionar o idioma chinês, após um recarregamento do navegador.

    1.4 Seleção de idioma no Zabbix

    Note

    Se seu idioma preferido não estiver disponível no frontend do Zabbix, não se preocupe, isso simplesmente significa que a tradução é ou incompleta ou ainda não está disponível. O Zabbix é um projeto open-source que depende de contribuições da comunidade para as traduções, então você pode ajudar melhorando com suas próprias traduções.

    Visite a página de tradução em https://translate.zabbix.com/ para auxiliar nos esforços de tradução. Uma vez que sua tradução esteja completa e revisada, será incluída na próxima versão menor do Zabbix. Suas contribuições ajudam a tornar o Zabbix mais acessível e melhoram a experiência geral do usuário para todos.Quando você estiver satisfeito com as traduções disponíveis, clique em Next. Você será então levado a uma tela para verificar que todos os pré-requisitos estão atendidos. Se algum dos pré-requisitos não for cumprido, resolva esses problemas primeiro. No entanto, se tudo estiver em ordem, você deve ser capaz de prosseguir clicando em Next.

    1.5 Pré-requisitos do Zabbix

    Na próxima página, você configurará os parâmetros de conexão com o banco de dados:

    1. Select the Database Type: Escolha entre MySQL ou PostgreSQL dependendo da sua configuração.
    2. Enter the Database Host: Forneça o endereço IP ou nome DNS do seu servidor de banco de dados. Use a porta 3306 para MariaDB/MySQL ou 5432 para PostgreSQL.
    3. Enter the Database Name: Especifique o nome do seu banco de dados. No nosso caso, é zabbix. Se você estiver usando PostgreSQL, também precisará fornecer o nome do esquema, que no nosso caso é zabbix_server.
    4. Enther the Database Schema: Somente para usuários de PostgreSQL, insira o nome do esquema criado para o servidor Zabbix, que no nosso caso é zabbix_server.
    5. Enter the Database User: Insira o usuário do banco de dados criado para a interface web frontal, lembre-se que em nossa guia de instalação básica criamos 2 usuários zabbix-web e zabbix-srv. Um para a frente e o outro para nosso servidor Zabbix, então aqui usaremos o usuário zabbix-web. Insira a senha correspondente para este usuário.

    Certifique-se de que a opção Database TLS encryption não está selecionada, e em seguida clique em Next step para prosseguir.

    1.6 Conexões do Zabbix

    Você está quase terminando a configuração! Os últimos passos envolvem:

    1. Assigning an Instance Name: Escolha um nome descritivo para sua instância Zabbix.
    2. Selecting the Timezone: Escolha o fuso horário que corresponde à sua localização ou ao seu fuso horário preferido para a interface do Zabbix.
    3. Setting the Default Time Format: Selecione o formato de tempo padrão que você prefere usar.
    4. Criptografar conexões da interface web: Marquei esta caixa, mas você não deve fazer isso. Esta caixa é para criptografar as comunicações entre a frente do Zabbix e seu navegador. Vamos abordar isso mais tarde. Uma vez que essas configurações estejam configuradas, você pode concluir a instalação e prosseguir com quaisquer etapas de configuração final conforme necessário.
    Note

    É uma boa prática definir o servidor Zabbix para o fuso horário UTC, especialmente quando gerenciando sistemas em múltiplos fusos horários. Usar UTC ajuda a garantir consistência em ações e eventos sensíveis ao tempo, pois o fuso horário do servidor é frequentemente usado para calcular e exibir informações relacionadas ao tempo.

    1.7 Resumo do Zabbix

    Após clicar em Next step novamente, você será levado a uma página confirmando que a configuração foi bem-sucedida. Clique em Finish para concluir o processo de instalação.

    1.8 Instalar Zabbix

    Estamos agora prontos para fazer login:

    1.9 Login no Zabbix

    • Usuário: Admin
    • Senha: zabbix

    Isso conclui nosso tópico sobre a configuração do servidor Zabbix. Se você estiver interessado em segurança da frente, recomendo verificar o tópico Segurança do Zabbix para orientações adicionais e melhores práticas.

    Tip

    Se você não conseguir salvar sua configuração no final, certifique-se de que executou as instruções relacionadas ao SELinux ou tenha o SELinux desativado. Também verifique se a pasta /etc/zabbix/web é gravável pelo usuário do webservice (geralmente wwwrun ou www)

    Conclusão

    Com a instalação e configuração da frente de usuário Zabbix agora concluída, você configurou com sucesso a interface do usuário para seu sistema de monitoramento Zabbix. Este processo incluiu a instalação dos pacotes necessários, configuração de um servidor web e um motor PHP, configuração da conexão com o banco de dados e personalização das configurações da frente.

    Nesta etapa, sua instância do Zabbix está em funcionamento, fornecendo a base para monitoramento avançado e alertas. Nos próximos capítulos, vamos nos aprofundar no ajuste fino do Zabbix, otimização de desempenho e exploração das principais características que o transformam em uma plataforma poderosa de observabilidade.

    Agora que seu ambiente Zabbix está funcionando, vamos levar isso ao próximo nível.
