    Installation d'une base de données PostgreSQL

    À la place de MariaDB/MySQL, vous pouvez choisir d'utiliser PostgreSQL comme backend de base de données pour Zabbix. Similaire à MariaDB, PostgreSQL peut être installé en utilisant soit les paquets fournis par le gestionnaire d'opérateur système ou les dépôts officiels PostgreSQL.

    Si vous avez déjà installé MariaDB dans la section précédente, vous pouvez sauter cette section.

    À ce jour, PostgreSQL 13-18 est pris en charge par Zabbix. Vérifiez la documentation de Zabbix pour obtenir une liste à jour des versions prises en charge pour votre version de Zabbix. Généralement, il est une bonne idée d'utiliser la dernière version prise en charge par Zabbix.

    Extension TimescaleDB

    Zabbix prend également en charge l'extension TimescaleDB mais, en raison de sa nature avancée, nous ne couvrirons pas ce sujet dans ce chapitre. Consultez Partitioning PostgreSQL with TimescaleDB pour des instructions détaillées sur ce sujet.

    Notez que si vous souhaitez utiliser les paquets RPM de TimescaleDB fournis par Timescale, vous devrez installer PostgreSQL à partir des dépôts officiels PostgreSQL au lieu des paquets fournis par le gestionnaire d'opérateur système. Si vous choisissez d'installer PostgreSQL à partir des paquets fournis par le gestionnaire d'opérateur système, vous devrez compiler et installer l'extension TimescaleDB à partir de sources.

    Note supplémentaire : TimescaleDB ne fournit pas de paquets pour SUSE Linux Enterprise Server (SLES) ou openSUSE Leap. Au lieu de cela, Suse fournit l'extension TimescaleDB dans leurs propres dépôts. Mais pour que cela fonctionne, vous devrez installer PostgreSQL à partir des paquets fournis par le gestionnaire d'opérateur système au lieu des dépôts officiels PostgreSQL.

    Installation du serveur et du client PostgreSQL à partir de paquets fournis par le gestionnaire d'opérateur système

    Pour installer le serveur PostgreSQL par défaut de la distribution, exécutez les commandes suivantes :

    Installation du serveur Postgres

    Red Hat 

    dnf install postgresql-server postgresql-client postgresql-contrib

    SUSE 

    zypper install postgresql-server postgresql postgresql-contrib

    Ubuntu 

    sudo apt install postgresql postgresql-client postgresql-contrib

    Cette commande téléchargera et installera à la fois les paquets serveur et client, vous permettant de configurer, configurer et interagir avec votre base de données PostgreSQL.

    Initialisation de la base de données requise sur Red Hat

    En raison des politiques pour les distributions familiales Red Hat, le service PostgreSQL ne initialise pas une base de données vide nécessaire au bon fonctionnement de PostgreSQL. Donc pour Red Hat, nous devons initialiser une base de données vide avant de continuer :

    Red Hat 

    postgresql-setup --initdb --unit postgresql

    Sur SUSE et Ubuntu, le service Systemd fourni par l'OS initiera automatiquement une base de données vide lors du premier démarrage.

    Une fois l'installation terminée, vous pouvez passer à la section Démarrer la base de données PostgreSQL.

    Installation de PostgreSQL à partir des dépôts officiels PostgreSQL

    Si vous préférez installer PostgreSQL à partir des dépôts officiels PostgreSQL au lieu des paquets fournis par le gestionnaire d'opérateur système, la première étape est d'ajouter le dépôt PostgreSQL à votre système.

    Ajout du dépôt PostgreSQL

    Configurez le dépôt PostgreSQL avec les commandes suivantes :

    Consultez https://www.postgresql.org/download/linux/ pour plus d'informations.

    Ajouter le dépôt PostgreSQL

    Red Hat 

    # Install the repository RPM:
dnf install https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm

# Disable the built-in PostgreSQL module:
dnf -qy module disable postgresql

    SUSE 

    # Import the repository signing key:
rpm --import https://zypp.postgresql.org/keys/PGDG-RPM-GPG-KEY-SLES16

# Install the repository RPM:
zypper install https://download.postgresql.org/pub/repos/zypp/reporpms/SLES-16-x86_64/pgdg-suse-repo-latest.noarch.rpm

# Update the package lists:
zypper refresh

    openSUSE Leap

    Comme les paquets officiels de PostgreSQL sont spécifiquement construits pour être utilisés sur SUSE Linux Enterprise Server (SLES), vous obtiendrez une erreur en essayant d'installer le dépôt sur openSUSE Leap. Nous pouvons néanmoins ignorer ce problème en choisissant de "briser le paquet en ignorant certaines de ses dépendances" tant que vous correspondez à la version SLES avec votre version openSUSE :

    Problem: 1: nothing provides 'sles-release' needed by the to be installed pgdg-suse-repo-42.0-48PGDG.noarch
 Solution 1: do not install pgdg-suse-repo-42.0-48PGDG.noarch
 Solution 2: break pgdg-suse-repo-42.0-48PGDG.noarch by ignoring some of its dependencies

Choose from above solutions by number or cancel [1/2/c/d/?] (c): 2
    Suse Linux Enterprise Server

    Sur SUSE Linux Enterprise Server (SLES), assurez-vous d'être abonné au dépôt "SUSE Package Hub extension" pour accéder aux paquets dépendances nécessaires à l'installation officielle de PostgreSQL. Sur SLES 15 vous aurez également besoin du module "Desktop Applications":

    # On SLES 16
suseconnect -p PackageHub/16.0/x86_64

# On SLES 15
SUSEConnect -p sle-module-desktop-applications/15.7/x86_64
SUSEConnect -p PackageHub/15.7/x86_64

    Ubuntu 

    # Import the repository signing key:
sudo apt install curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc

# Create the repository configuration file:
sudo sh -c 'echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'

# Update the package lists:
sudo apt update

    Installation du serveur et du client PostgreSQL

    Avec les dépôts PostgreSQL configurés, vous êtes maintenant prêt à installer le serveur et les paquets clients PostgreSQL. Cela fournira les composants nécessaires pour exécuter et gérer votre base de données.

    Installation de PostgreSQL depuis les dépôts officiels

    Red Hat 

    # Install Postgres server:
dnf install postgresql17 postgresql17-server postgresql17-contrib

    SUSE 

    zypper install postgresql17 postgresql17-server postgresql17-contrib

    Ubuntu 

    sudo apt install postgresql-17 postgresql-client-17

    Cette commande téléchargera et installera à la fois les paquets serveur et client, vous permettant de configurer, configurer et interagir avec votre base de données PostgreSQL.

    Ensuite, avant que nous puissions démarrer le serveur PostgreSQL, nous devons initialiser une nouvelle base de données vide :

    Initialisation d'une base de données PostgreSQL vide

    sudo /usr/pgsql-17/bin/postgresql-17-setup initdb

    Une fois l'installation terminée, vous pouvez passer à la section Démarrage de la base de données PostgreSQL.

    Démarrage de la base de données PostgreSQL

    Maintenant que PostgreSQL est installé, nous devons activer le service pour qu'il démarre automatiquement au démarrage du système ainsi que lancer immédiatement. Utilisez la commande suivante pour accomplir cela :

    Activation et démarrage du service PostgreSQL

    Pour les paquets fournis par le gestionnaire d'opérateur système 

    sudo systemctl enable postgresql --now

    Pour les paquets officiels de PostgreSQL : 

    sudo systemctl enable postgresql-17 --now

    Cette commande activera et démarrera le service PostgreSQL. Avec le service maintenant en cours d'exécution, vous pouvez vérifier que l'installation a été réussie en vérifiant la version de PostgreSQL à l'aide de la commande suivante :

    Vérification de la version de PostgreSQL

    psql -V

    La sortie attendue ressemblera à ceci :

    Exemple de version PostgreSQL 
    localhost:~ $ psql -V
psql (PostgreSQL) 17.7

    Pour vous assurer que le service PostgreSQL fonctionne correctement, vous pouvez vérifier son statut avec la commande suivante :

    Obtention du statut du service PostgreSQL

    Pour les paquets fournis par le gestionnaire d'opérateur système 

    sudo systemctl status postgresql

    Pour les paquets officiels de PostgreSQL : 

    sudo systemctl status postgresql-17

    Vous devriez voir une sortie similaire à celle-ci, indiquant que le service PostgreSQL est actif et en cours d'exécution :

    Sécurisation de la base de données PostgreSQL

    PostgreSQL gère les permissions d'accès différemment des MySQL et MariaDB. PostgreSQL se fie à un fichier appelé pg_hba.conf pour gérer qui peut accéder à la base de données, d'où, et quelle méthode de chiffrement est autorisée pour l'authentification.

    À propos du fichier pg_hba.conf

    L'authentification des clients dans PostgreSQL est configurée via le fichier pg_hba.conf où "HBA" signifie Host-Based Authentication. Ce fichier spécifie qui peut accéder à la base de données, d'où, et comment ils sont authentifiés. Pour plus de détails, vous pouvez consulter la documentation officielle PostgreSQL." https://www.postgresql.org/docs/current/auth-pg-hba-conf.html

    Ajoutez les lignes suivantes, l'ordre ici est important.

    Modification du fichier pg_hba

    Red Hat / SUSE 

    # for OS-provided packages
vi /var/lib/pgsql/data/pg_hba.conf

# for official packages
vi /var/lib/pgsql/17/data/pg_hba.conf

    Ubuntu 

    # for OS-provided packages
sudo vi /etc/postgresql/current/main/pg_hba.conf

# for official packages
sudo vi /etc/postgresql/17/main/pg_hba.conf

    Emplacement du fichier pg_hba

    Si vous ne trouvez pas les fichiers pg_hba.conf et postgres.conf à l'emplacement mentionné ci-dessus, vous pouvez demander à PostgreSQL lui-même de fournir l'emplacement en utilisant la commande suivante (à condition que PostgreSQL soit actuellement en cours d'exécution) :

    sudo -u postgres psql -t -c 'show hba_file';

    Le fichier pg_hba résultant devrait ressembler à ceci :

    Exemple de pg_hba

    # "local" is for Unix domain socket connections only
local    zabbix     zabbix-srv                                 scram-sha-256
local    all        all                                        peer
# IPv4 local connections
host     zabbix         zabbix-srv      <ip from zabbix server/24>     scram-sha-256
host     zabbix         zabbix-web      <ip from zabbix frontend/24>   scram-sha-256
host     all            all             127.0.0.1/32                   scram-sha-256
# IPv6 local connections:
host    zabbix          zabbix-srv      ::1/128                 scram-sha-256
host    zabbix          zabbix-web      ::1/128                 scram-sha-256
host    all             all             ::1/128                 ident

    Assurez-vous de conserver l'ordre des entrées

    L'ordre des entrées dans le fichier pg_hba.conf est crucial, car PostgreSQL traite ces règles séquentiellement. Assurez-vous que les règles spécifiques pour les utilisateurs zabbix-srv et zabbix-web sont placées avant toute règle plus large comme la règle par défaut all qui pourrait potentiellement les annuler.

    Après avoir modifié le fichier pg_hba.conf, n'oubliez pas de redémarrer PostgreSQL sinon les paramètres ne seront pas appliqués. Mais avant de redémarrer, modifions également le fichier postgresql.conf et permettons à notre base de données d'écouter sur l'interface réseau pour accepter des connexions du serveur Zabbix. PostgreSQL ne permet par défaut que les connexions depuis un socket Unix.

    Modification du fichier postgresql.conf

    Red Hat / SUSE 

    # for OS-provided packages
vi /var/lib/pgsql/data/postgresql.conf

# for official packages
vi /var/lib/pgsql/17/data/postgresql.conf

    Ubuntu 

    # for OS-provided packages
sudo vi /etc/postgresql/current/main/postgresql.conf

# for official packages
sudo vi /etc/postgresql/17/main/postgresql.conf

    Localisez la ligne suivante :

    #listen_addresses = 'localhost'

    et remplacez-la par :

    listen_addresses = '*'
    Note

    Cela permettra à PostgreSQL d'accepter des connexions depuis n'importe quelle interface réseau, pas seulement la machine locale. En production, il est probablement une bonne idée de limiter qui peut se connecter à la base de données.

    Après avoir effectué ce changement, redémarrez le service PostgreSQL pour appliquer les nouvelles configurations :

    Redémarrage du serveur de base de données

    Pour les paquets fournis par le gestionnaire d'opérateur système 

    sudo systemctl restart postgresql

    Pour les paquets officiels 

    sudo systemctl restart postgresql-17

    Tip

    Si le service ne redémarre pas, vérifiez le fichier pg_hba.conf pour toute erreur de syntaxe, car des entrées incorrectes ici peuvent empêcher PostgreSQL de démarrer.

    Création de l'instance de base de données Zabbix

    Avec les paquets nécessaires installés, vous êtes maintenant prêt à créer la base de données et les utilisateurs pour le serveur et l'interface frontale Zabbix.Les packages PostgreSQL créent automatiquement un utilisateur par défaut postgres lors de l'installation, qui dispose des privilèges administratifs sur l'instance PostgreSQL. Pour administrer la base de données, vous devrez exécuter les commandes en tant que l'utilisateur postgres.

    Tout d'abord, créez l'utilisateur du serveur Zabbix (aussi appelé "rôle" dans PostgreSQL) :

    Créer les utilisateurs du serveur

    sudo -u postgres createuser --pwprompt zabbix-srv
Enter password for new role: <server-password>
Enter it again: <server-password>

    Ensuite, créez l'utilisateur de la console frontale qui sera utilisé pour se connecter à la base de données :

    Créer l'utilisateur de la console frontale

    sudo -u postgres createuser --pwprompt zabbix-web
Enter password for new role: <frontend-password>
Enter it again: <frontend-password>

    Maintenant que les utilisateurs ont été créés, le prochain pas est de créer la base de données Zabbix. Exécutez la commande suivante pour créer la base de données zabbix avec le propriétaire défini sur zabbix-srv et l'encodage des caractères défini sur Unicode comme requis par Zabbix :

    Créer la base de données

    sudo -u postgres createdb -E Unicode -T template0 -O zabbix-srv zabbix
    Qu'est-ce que ce 'template0'?

    Dans PostgreSQL, template0 est un modèle de base de données par défaut qui sert de copie vierge du système de base de données. Lors de la création d'une nouvelle base de données en utilisant template0, cela garantit que la nouvelle base de données commence avec une feuille blanche, sans aucun objet ou configuration préexistants qui pourraient être présents dans d'autres modèles. Cela est particulièrement utile lorsque vous souhaitez créer une base de données avec des paramètres spécifiques ou des extensions sans hériter d'éléments indésirables provenant d'autres modèles.

    Une fois la base de données créée, vous devriez vérifier la connexion et vous assurer que la session utilisateur correcte est active. Pour cela, connectez-vous à la base de données zabbix en utilisant l'utilisateur zabbix-srv :

    Se connecter en tant qu'utilisateur zabbix-srv

    psql -d zabbix -U zabbix-srv

    Après la connexion, exécutez la requête SQL suivante pour confirmer que les paramètres session_user et current_user sont définis sur zabbix-srv :

    zabbix=> SELECT session_user, current_user;
 session_user | current_user
--------------+--------------
 zabbix-srv   | zabbix-srv
(1 row)

    Si la sortie correspond, vous êtes connecté à la base de données avec l'utilisateur correct.

    PostgreSQL diffère considérablement de MySQL ou MariaDB dans plusieurs aspects, et l'un des principaux éléments qui le distingue est son utilisation des schémas. Contrairement à MySQL, où les bases de données sont plus autonomes, le système de schémas de PostgreSQL fournit un environnement structuré et multi-utilisateurs au sein d'une seule base de données.

    Les schémas agissent comme des conteneurs logiques au sein d'une base de données, permettant à plusieurs utilisateurs ou applications d'accéder et de gérer les données indépendamment sans conflits. Cette fonctionnalité est particulièrement précieuse dans les environnements où plusieurs utilisateurs ou applications doivent interagir avec le même serveur de base de données simultanément. Chaque utilisateur ou application peut avoir son propre schéma, prévenant toute interférence accidentelle entre leurs données.

    Note

    PostgreSQL vient avec un schéma par défaut, généralement appelé public, mais en général, il est une bonne pratique de créer des schémas personnalisés pour mieux organiser et séparer les objets de la base de données, surtout dans des environnements complexes ou multi-utilisateurs.

    Pour plus d'informations détaillées, je recommande de consulter le guide approfondi à cette URI, https://hevodata.com/learn/postgresql-schema/#schema qui explique les avantages et les cas d'utilisation des schémas dans PostgreSQL.

    Pour finaliser la configuration initiale de la base de données pour Zabbix, nous devons configurer les permissions du schéma pour les utilisateurs zabbix-srv et zabbix-web.

    Tout d'abord, nous créons un schéma personnalisé nommé zabbix_server et attribuons la propriété à l'utilisateur zabbix-srv :

    Créer le schéma de la base de données

    zabbix=> CREATE SCHEMA zabbix_server AUTHORIZATION "zabbix-srv";

    Ensuite, nous définissons le search path sur zabbix_server pour qu'il soit par défaut pour la session actuelle :

    Définir le chemin de recherche

    zabbix=> SET search_path TO "zabbix_server";
    Tip

    Si vous préférez ne pas définir manuellement le chemin de recherche chaque fois que vous vous connectez en tant qu'utilisateur zabbix-srv, vous pouvez configurer PostgreSQL pour utiliser automatiquement le chemin de recherche souhaité. Exécutez la commande SQL suivante pour définir le chemin de recherche par défaut pour le rôle zabbix-srv :

    zabbix=> ALTER ROLE "zabbix-srv" SET search_path = zabbix_server;

    Cette commande garantit que chaque fois que l'utilisateur zabbix-srv se connecte à la base de données, le search_path est automatiquement défini sur zabbix_server.

    Pour confirmer la configuration du schéma, vous pouvez lister les schémas existants :

    Vérifier l'accès au schéma

    zabbix=> \dn
          List of schemas
     Name      |       Owner
---------------+-------------------
 public        | pg_database_owner
 zabbix_server | zabbix-srv
(2 rows)

    À ce stade, l'utilisateur zabbix-srv a un accès complet au schéma, mais l'utilisateur zabbix-web a toujours besoin de permissions appropriées pour se connecter et interagir avec la base de données. Tout d'abord, nous accordons des privilèges USAGE sur le schéma afin que l'utilisateur zabbix-web puisse se connecter :

    Accorder un accès au schéma pour l'utilisateur zabbix-web

    zabbix=> GRANT USAGE ON SCHEMA zabbix_server TO "zabbix-web";

    Maintenant, l'utilisateur zabbix-web a les permissions appropriées pour interagir avec le schéma tout en maintenant la sécurité en limitant les permissions aux opérations essentielles.

    Si vous êtes prêt, vous pouvez quitter la base de données et revenir à votre shell Linux.

    Quitter l'invite de commande de la base de données

    zabbix=> \q

    À ce stade, votre base de données Zabbix est prête, mais avant qu'elle ne puisse être utilisée par Zabbix, nous devons encore la remplir avec les tables et les données initiales nécessaires, mais cela sera couvert dans la section suivante lors de l'installation du serveur Zabbix.

    Si vous prévoyez d'installer le serveur Zabbix sur une machine différente que celle hébergeant la base de données, vous devrez ouvrir le pare-feu hôte pour permettre les connexions entrantes à le serveur de la base de données. Par défaut, PostgreSQL écoute sur le port 5432.

    Ajouter des règles au pare-feu

    Red Hat / SUSE 

    firewall-cmd --add-service=postgresql --permanent
firewall-cmd --reload

    Ubuntu 

    sudo ufw allow 5432/tcp

    Remplir la base de données Zabbix

    Au cours de l'installation du logiciel de base de données précédemment, nous avons créé les utilisateurs nécessaires, la base de données et le schéma pour Zabbix, cependant, Zabbix attend certaines tables, schémas, images et autres éléments présents dans la base de données. Pour configurer correctement la base de données, nous devons la remplir avec les schémas requis.

    Tout d'abord, nous avons besoin d'installer les scripts SQL Zabbix qui contiennent les scripts d'import nécessaires pour la base de données.

    Installer les scripts SQL

    Red Hat 

    dnf install zabbix-sql-scripts

    SUSE 

    zypper install zabbix-sql-scripts

    Ubuntu 

    sudo apt install zabbix-sql-scripts

    Ensuite, vous devez préparer le schéma de la base de données : décompressez les fichiers de schéma nécessaires en exécutant la commande suivante :

    Décompresser le correctif DB

    Red Hat / SUSE 

    gzip -d /usr/share/zabbix/sql-scripts/postgresql/server.sql.gz

    Ubuntu

    Note

    Zabbix semble aimer changer les emplacements des scripts pour remplir la base de données à chaque version ou même entre versions. Si vous rencontrez une erreur, consultez la documentation Zabbix, il y a de fortes chances que certains emplacements aient été modifiés.
