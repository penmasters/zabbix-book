    Установка интерфейса

    Перед настройкой интерфейса Zabbix убедитесь, что система соответствует требованиям и подготовлена в соответствии с предыдущей главой: Начало работы. Этот сервер может быть тем же самым, где ранее были установлены пакеты Zabbix-сервера, или это может быть отдельная машина.

    Выполните все последующие шаги на сервере, предназначенном для интерфейса.

    Установка интерфейса с NGINX

    установить пакеты интерфейса

    Red Hat 

    # List all available php modules and active php-8.2
dnf module list php -y
dnf module enable php:8.2
# When using MySQL/MariaDB
dnf install zabbix-nginx-conf zabbix-web-mysql
# or when using PostgreSQL
dnf install zabbix-nginx-conf zabbix-web-pgsql

    SUSE 

    # When using MySQL/MariaDB
zypper install zabbix-nginx-conf zabbix-web-mysql php8-openssl php8-xmlreader php8-xmlwriter
# or when using PostgreSQL
zypper install zabbix-nginx-conf zabbix-web-pgsql php8-openssl php8-xmlreader php8-xmlwriter

    Suse Linux Enterprise Server

    На SUSE Linux Enterprise Server (SLES) убедитесь, что вы подписаны на репозиторий "SUSE Linux Enterprise Module Web and Scripting", чтобы получить доступ к необходимым пакетам PHP 8, требуемым для установки интерфейса Zabbix: (в версиях SLES < 16 команда "SUSEConnect" вместо "suseconnect")

    suseconnect -p sle-module-web-scripting/16/x86_64

    Актуальный URL для модуля веб-скриптинга может отличаться в зависимости от конкретного пакета обновления. Используйте следующую команду, чтобы определить правильный.

    suseconnect --list-extensions

    Ubuntu 

    # When using MySQL/MariaDB
sudo apt install zabbix-frontend-php php8.3-mysql zabbix-nginx-conf
# or when using PostgreSQL
sudo apt install zabbix-frontend-php php8.3-pgsql zabbix-nginx-conf

    Эта команда установит пакеты интерфейса вместе с необходимыми зависимостями для NGINX.

    С версии SUSE 16 SELinux является по умолчанию модулем безопасности вместо AppArmor. По умолчанию PHP-FPM не разрешен SELinux на SUSE для - отображения памяти выполнения, необходимой для JIT компиляции PHP, - подключения к серверу Zabbix или - подключения к серверу базы данных через TCP. Мы должны сообщить SELinux о том, чтобы позволить все это:

    SELinux: Разрешить PHP-FPM отображать память выполнения

    setsebool -P httpd_execmem 1
setsebool -P httpd_can_connect_zabbix 1
setsebool -P httpd_can_network_connect_db 1
    Tip

    Для устранения неполадок с SELinux рекомендуется установить пакет setroubleshoot, который будет записывать любые отказы SELinux в системный журнал и предоставлять предложения по их решению.

    В зависимости от настроек Linux по умолчанию, PHP-FPM может быть не разрешен Systemd для записи в директорию /etc/zabbix/web, необходимую для установки интерфейса Zabbix. Чтобы это разрешить нам нужно создать файл drop-in:

    Systemd: Разрешить PHP-FPM записывать в /etc/zabbix/web

    systemctl edit php-fpm

    Это откроет редактор для создания файла drop-in /etc/systemd/system/php-fpm.service.d/override.conf который будет переопределять или расширять существующий файл службы.

    Добавьте следующие строки в файл:

    [Service]
ReadWritePaths=/etc/zabbix/web

    Затем выйдите из редактора и перезагрузите конфигурацию Systemd:

    systemctl daemon-reload
    Как Systemd препятствует записи PHP-FPM в /etc/zabbix/web?

    На многих современных дистрибутивах Linux, Systemd использует функцию безопасности, известную как песочница, чтобы ограничить возможности служб. Это делается для повышения безопасности путем ограничения доступа служб только к тем ресурсам, которые им нужны для работы. По умолчанию PHP-FPM может быть ограничен от записи в определенные директории, включая /etc/zabbix/web, чтобы предотвратить потенциальные уязвимости безопасности. Это контролируется директивами Systemd ProtectSystem и ReadWritePaths, которые регулируют доступ к файловой системе служб.

    Tip

    Обычно запись в /etc/zabbix/web требуется только при начальной настройке интерфейса Zabbix. После завершения настройки вы можете удалить файл drop-in снова, чтобы еще больше усилить безопасность вашей системы.

    Первым делом нам нужно изменить конфигурационный файл NGINX, чтобы мы не использовали стандартную конфигурацию и обслуживали интерфейс Zabbix на порту 80.

    Измените конфигурацию nginx для Red Hat

    vi /etc/nginx/nginx.conf

    Если вы используете Ubuntu, не нужно редактировать nginx.conf просто выполните sudo unlink /etc/nginx/sites-enabled/default

    В этом файле конфигурации найдите следующий блок, который начинается с server {:

    Оригинальная конфигурация

    server {
    listen 80;
    listen [::]:80;
    server_name *;
...
    Tip

    Этот блок может отличаться в зависимости от вашей дистрибутивы и версии NGINX.

    Затем закомментируйте любые listen и server_name директивы, чтобы отключить стандартную конфигурацию HTTP-сервера. Вы можете сделать это, добавив # в начало каждой строки, как показано ниже:

    Конфигурация после редактирования

    server {
    #listen 80;
    #listen [::]:80;
    #server_name *;
...

    Файл конфигурации Zabbix теперь должен быть изменен, чтобы взять на себя стандартный сервис на порту 80, который мы только что отключили. Откройте следующий файл для редактирования:

    Измените конфигурацию Zabbix для nginx

    sudo vi /etc/nginx/conf.d/zabbix.conf

    И измените следующие строки:

    Оригинальная конфигурация

    server {
#       listen          8080;
#       server_name     example.com;

        root    /usr/share/zabbix;

        index   index.php;
...

    Удалите # перед первыми двумя строками и измените их с правильным портом и доменом для вашего интерфейса.

    Tip

    Если у вас нет домена, вы можете заменить servername на _ как показано ниже:

    Конфигурация после редактирования

    server {
        listen          80;
        server_name     _;

         root    /usr/share/zabbix;

         index   index.php;

    Веб-сервер и служба PHP-FPM теперь готовы к активации и запуску при перезагрузке. Выполните следующие команды, чтобы включить их и немедленно запустить:

    Перезапустите службы интерфейса

    Red Hat / SUSE 

    systemctl enable nginx php-fpm --now

    Ubuntu 

    sudo systemctl enable nginx php8.3-fpm --now

    Давайте проверим, работает ли служба правильно и настроена ли она для автоматического запуска при следующей перезагрузке.

    Проверьте работу службы

    sudo systemctl status nginx
    Пример вывода

    Со службой, работающей и настроенной для автоматического запуска, последний подготовительный шаг включает изменение брандмауэра для разрешения входящего трафика HTTP. Выполните следующие команды:

    Настройте брандмауэр

    Red Hat / SUSE 

    firewall-cmd --add-service=http --permanent
firewall-cmd --reload

    Ubuntu 

    sudo ufw allow 80/tcp

    Откройте ваш браузер и перейдите по URL или IP вашего интерфейса:

    Настройка интерфейса

    http://<ip or dns of the zabbix frontend server>/

    Если все в порядке, вы должны увидеть страницу приветствия Zabbix. В случае ошибки проверьте конфигурацию снова или посмотрите файл журнала NGINX /var/log/nginx/error.log или выполните следующую команду:

    journalctl -xeu nginx

    Это поможет вам найти ошибки, которые вы сделали.

    При доступе к соответствующему URL должна появиться страница, подобная той, что показана ниже:

    Выберите подходящую локализацию

    Локализация en_US использует американский формат даты и 12-часовой часовой пояс, в то время как en_GB использует международный формат даты и 24-часовой часовой пояс.

    1.3 Выбор языка приветствия Zabbix

    Что если мы хотим установить китайский язык или другой из списка? Выполните следующую команду, чтобы получить список всех доступных локализаций для вашей ОС.

    Установите пакеты языка

    Red Hat 

    dnf list glibc-langpack-*

    SUSE 

    localectl list-locales

    Ubuntu 

    apt-cache search language-pack

    Пользователи на Ubuntu, вероятно, заметят следующую ошибку Локализация для языка "en_US" не найдена на веб-сервере."

    Это можно легко исправить с помощью следующих команд.

    sudo locale-gen en_US.UTF-8
sudo update-locale
sudo systemctl restart nginx php8.3-fpm

    Поиск пакета языка

    Red Hat 

    ~# dnf list glibc-langpack-* | grep zh

    На RedHat и Ubuntu команда выводит две строки; однако, учитывая определенный код языка, 'zh_CN', требуется установить только первый пакет. на SUSE либо только локализации C.UTF-8 и en_US.UTF-8 устанавливаются или все доступные локализации устанавливаются, в зависимости от того, установлен ли пакет glibc-locale или нет.

    Установите пакет локализации

    Red Hat 

    dnf install glibc-langpack-zh.x86_64
sudo systemctl restart nginx php-fpm

    SUSE 

    zypper install glibc-locale
sudo systemctl restart nginx php-fpm

    Ubuntu 

    sudo apt install language-pack-zh-hans
sudo systemctl restart nginx php8.3-fpm

    Когда мы вернемся теперь к нашему интерфейсу, мы сможем выбрать язык на китайском, после перезагрузки нашего браузера.

    1.4 Выбор языка Zabbix

    Note

    Если ваш предпочтительный язык недоступен в интерфейсе Zabbix, не волнуйтесь, это просто означает, что перевод либо неполон, либо еще не доступен. Zabbix - это проект с открытым исходным кодом, который зависит от вкладов сообщества для перевода. Вы можете помочь улучшить его, сделав собственный перевод.

    Посетите страницу перевода по адресу https://translate.zabbix.com/ для помощи в усилиях по переводам. Как только ваш перевод будет завершен и проверен, он будет включен в следующую версию патча Zabbix. Ваши вклады помогают сделать Zabbix более доступным и улучшают общее пользовательский опыт для всех.Когда вы удовлетворены доступными переводами, нажмите Next. Вы перейдете на экран для проверки выполнения всех предварительных условий. Если какие-либо из них не выполнены, сначала устраните эти проблемы. Однако если все в порядке, вы сможете продолжить, нажав Next.

    1.5 Предварительные условия Zabbix

    На следующей странице вам нужно будет настроить параметры подключения к базе данных:

    1. Select the Database Type: Выберите MySQL или PostgreSQL в зависимости от вашей установки.
    2. Enter the Database Host: Укажите IP-адрес или имя DNS вашего сервера базы данных. Используйте порт 3306 для MariaDB/MySQL или 5432 для PostgreSQL.
    3. Enter the Database Name: Укажите имя вашей базы данных. В нашем случае это zabbix. Если вы используете PostgreSQL, вам также нужно будет указать имя схемы, которое в нашем случае является zabbix_server.
    4. Enther the Database Schema: Только для пользователей PostgreSQL, укажите имя схемы, созданной для сервера Zabbix, которое в нашем случае является zabbix_server.
    5. Enter the Database User: Введите пользователя базы данных, созданный для веб-интерфейса. Помните, что в нашей базовой инструкции по установке мы создали 2 пользователей zabbix-web и zabbix-srv. Один для веб-интерфейса и другой для нашего сервера Zabbix, поэтому здесь мы будем использовать пользователя zabbix-web. Введите соответствующий пароль для этого пользователя.

    Убедитесь, что опция Database TLS encryption не выбрана, а затем нажмите Next step для продолжения.

    1.6 Подключения Zabbix

    Вы почти закончили установку! Последние шаги включают:

    1. Assigning an Instance Name: Выберите описательное имя для вашего экземпляра Zabbix.
    2. Selecting the Timezone: Выберите часовой пояс, соответствующий вашему местоположению или предпочитаемому часовому поясу для интерфейса Zabbix.
    3. Setting the Default Time Format: Выберите предпочтительный формат времени.
    Note

    Хорошей практикой является установка сервера Zabbix в часовой пояс UTC, особенно при управлении системами в нескольких часовых поясах. Использование UTC помогает обеспечить согласованность во временных действиях и событиях, так как часовой пояс сервера часто используется для расчета и отображения информации о времени.

    1.7 Итоги Zabbix

    После повторного нажатия Next step вы перейдете на страницу, подтверждающую успешную конфигурацию. Нажмите Finish для завершения процесса установки.

    Теперь мы готовы войти:

    1.9 Вход в Zabbix

    Это завершает нашу тему по установке сервера Zabbix. Если вас интересует защита вашего веб-интерфейса, рекомендую ознакомиться с темой "Защита Zabbix" для получения дополнительных советов и лучших практик.

    Tip

    Если вы не можете сохранить свою конфигурацию в конце, убедитесь, что вы выполнили инструкции по SELinux или отключили SELinux. Также проверьте, доступен ли каталог /etc/zabbix/web для записи пользователем веб-сервиса (обычно wwwrun или www)

    Заключение

    С завершением установки и настройки веб-интерфейса Zabbix вы успешно создали пользовательский интерфейс для системы мониторинга Zabbix. Этот процесс включал установку необходимых пакетов, настройку веб-сервера и движка PHP, настройку подключения к базе данных и настройку параметров веб-интерфейса.

    На данном этапе ваш экземпляр Zabbix функционирует, предоставляя основу для продвинутого мониторинга и оповещений. В следующих главах мы углубимся в настройку Zabbix, оптимизацию производительности и изучение ключевых функций, которые превращают его в мощную платформу наблюдения.

    Теперь что ваша среда Zabbix запущена, давайте поднимем ее на следующий уровень.
