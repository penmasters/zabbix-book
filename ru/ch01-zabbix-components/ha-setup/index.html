    Настройка HA

    В этом разделе мы настроим Zabbix в конфигурации высокой доступности (HA). Эта встроенная функция, представленная в Zabbix 6, является важным улучшением, обеспечивающим непрерывный мониторинг даже при отказе сервера Zabbix. В режиме HA, когда один сервер Zabbix выходит из строя, другой может беспроблемно взять на себя его функции.

    Для этого руководства мы будем использовать два сервера Zabbix и одну базу данных, но конфигурация позволяет добавить больше серверов Zabbix по мере необходимости.

    1.10 HA Настройка

    Важно отметить, что настройка HA для Zabbix проста и обеспечивает резервирование, не требуя сложных функций, таких как балансировка нагрузки. Только один узел будет активным, все остальные будут находиться в режиме ожидания. Все серверы Zabbix в кластере HA будут мониторить активный узел через heartbeat с использованием общей базы данных. Это не требует никакого дополнительного программного обеспечения для кластеризации или даже портов брандмауэра для сервера Zabbix. Однако, для фронтенда мы будем использовать Keepalived, чтобы предоставить виртуальный IP-адрес (VIP) для целей переключения.

    Как и при базовой конфигурации, мы будем документировать ключевые детали для серверов в этой HA-конфигурации. Ниже приведен список серверов и место для добавления их соответствующих IP-адресов для вашего удобства:

    Сервер IP-адрес
    Zabbix Server 1
    Zabbix Server 2
    База данных
    Виртуальный IP
    Note

    Наша база данных (DB) в этой конфигурации не настроена для HA. Поскольку это не компонент Zabbix, вам потребуется реализовать свое решение для базы данных, например, кластер SAN с высокой доступностью или кластер базы данных. Конфигурация кластера базы данных выходит за рамки этого руководства и не связана с Zabbix, поэтому она здесь не рассматривается.

    Установка базы данных

    См. раздел Компоненты Zabbix: База данных для подробных инструкций по настройке базы данных. Этот раздел предоставляет пошаговое руководство по установке PostgreSQL или MariaDB на отдельном узле, работающем с Ubuntu, SUSE или Rocky Linux. Те же шаги установки применимы при настройке базы данных для этой конфигурации.

    Установка кластера Zabbix

    Настройка кластера Zabbix включает в себя настройку нескольких серверов Zabbix для совместной работы, обеспечивая высокую доступность. Хотя процесс похож на установку одного сервера Zabbix, для включения HA (высокой доступности) требуются дополнительные шаги конфигурации.

    Начните с подготовки систем и установкой сервера Zabbix на всех системах, следуя инструкциям разделов Подготовка сервера к работе с Zabbix и Установка сервера Zabbix главы Компоненты Zabbix.

    Обратите внимание на следующее:

    • пропустите шаг заполнения базы данных на всех серверах, кроме первого, так как база данных общая для всех серверов Zabbix.
    • пропустите включение и запуск службы zabbix-server на всех серверах, поскольку мы будем ее запускать позже после завершения конфигурации HA.
    • убедитесь, что все серверы Zabbix могут подключаться к базе данных. Например, если вы используете PostgreSQL, убедитесь, что файл pg_hba.conf настроен для разрешения соединений с всех серверов Zabbix.
    • все серверы Zabbix должны использовать одинаковое имя базы данных, пользователя и пароль для подключения к базе данных.
    • все серверы Zabbix должны быть одной версии.

    Когда все серверы Zabbix установлены и настроены для доступа к базе данных, мы можем приступить к конфигурации HA.

    Настройка первого сервера Zabbix

    Добавьте новый файл конфигурации для установки HA на первом сервере Zabbix:

    Добавление конфигурации сервера Zabbix с высокой доступностью

    sudo vi /etc/zabbix/zabbix_server.d/high-availability.conf

    Вставьте следующую строку в файл конфигурации для включения режима HA.

    HANodeName=zabbix1  # or choose a name you prefer

    Укажите адрес узла фронтенда для сценариев переключения:

    NodeAddress=<Zabbix server 1 ip>:10051
    Warning

    NodeAddress должен совпадать с IP-адресом или полным доменным именем узла сервера Zabbix. Без этого параметра фронтенд Zabbix не сможет подключиться к активному узлу. В результате фронтенд будет не в состоянии отображать статус очереди и другие данные.

    Настройка второго сервера Zabbix

    Повторите шаги настройки для второго сервера Zabbix. Адаптируйте HANodeName и NodeAddress по необходимости для этого сервера.

    Конфигурация высокой доступности сервера Zabbix 2 high-availability.conf 
    HANodeName=zabbix2  # or choose a name you prefer
NodeAddress=<Zabbix server 2 ip>:10051

    Вы можете добавить больше серверов, повторив те же шаги и убедившись, что каждый сервер имеет уникальный HANodeName и правильное значение NodeAddress.

    Запуск сервера Zabbix

    После настройки обоих серверов, включите и запустите службу zabbix-server на каждом:

    Включение и запуск службы zabbix-server

    sudo systemctl enable zabbix-server --now

    Проверка конфигурации

    Проверьте файлы журнала на обоих серверах, чтобы убедиться, что они успешно запущены и работают в соответствующем режиме HA.

    На первом сервере:

    Проверка журналов на сообщения HA

    sudo grep HA /var/log/zabbix/zabbix_server.log

    В системных журналах вы должны увидеть следующие записи, указывающие на инициализацию менеджера высокой доступности (HA):

    Сообщения журнала HA на активном узле 
    localhost:~> sudo grep HA /var/log/zabbix/zabbix_server.log
22597:20240309:155230.353 starting HA manager
22597:20240309:155230.362 HA manager started in active mode

    Эти сообщения в журналах подтверждают, что процесс менеджера HA запущен и принял активную роль. Это означает, что экземпляр Zabbix теперь является основным узлом в кластере HA, обрабатывающим все операции мониторинга. При событии переключения, другой резервный узел примет на себя управление в соответствии с конфигурацией HA.

    Выполнение того же команды на втором сервере (и любом дополнительном узле):

    Сообщения журнала HA на резервном узле 
    localhost:~> sudo grep HA /var/log/zabbix/zabbix_server.log
22304:20240309:155331.163 starting HA manager
22304:20240309:155331.174 HA manager started in standby mode

    Эти сообщения подтверждают, что процесс менеджера HA был запущен и успешно запущен в режиме ожидания. Это указывает на то, что узел работает, но не является активным узлом HA, ожидая дальнейших переходов состояния в соответствии с конфигурацией HA.

    На этом этапе ваш кластер Zabbix успешно настроен для высокой доступности (HA). Системные журналы подтверждают, что менеджер HA был инициализирован и работает в режиме ожидания, указывая на наличие механизмов переключения. Эта конфигурация обеспечивает непрерывный мониторинг, даже в случае отказа сервера, позволяя автоматическое переключение ролей в соответствии с конфигурацией HA.

    Установка фронтенда

    Перед установкой и настройкой веб-сервера необходимо установить какое-либо программное обеспечение для кластеризации или использовать балансировщик нагрузки перед Zabbix frontend, чтобы иметь возможность использования общего виртуального IP-адреса (VIP).

    Note

    Существует несколько вариантов программного обеспечения для кластеризации и балансировщиков нагрузок, включая Pacemaker, Corosync, HAProxy, F5 Big-Ip, Citrix NetScaler и различные облачные балансировщики нагрузок. Каждое из этих решений предлагает ряд функций и возможностей, превышающих простую предоставление VIP для переключения. Однако в рамках этого руководства мы сосредоточимся на минимальном подходе к обеспечению высокой доступности для фронтенда Zabbix с использованием Keepalived.

    Keepalived — это помощник, который гарантирует, что один компьютер возьмет на себя управление, если другой выйдет из строя. Он предоставляет им общий волшебный IP-адрес, чтобы пользователи не заметили отказа сервера. Если основной узел выходит из строя, резервный сразу же принимает его место.

    Keepalived — это минимальное программное обеспечение для кластеризации, которое позволяет использовать VIP для услуг фронтенда, обеспечивая бесшовное переключение и непрерывность обслуживания.

    Высокая доступность на SUSE Linux Enterprise Server (SLES)

    На SUSE Linux Enterprise Server (SLES) Keepalived не входит в стандартную подписку, поэтому его нет в стандартных репозиториях.

    Чтобы установить и использовать Keepalived на SLES поддерживаемым способом, вам потребуется получить дополнительную подписку 'SUSE Linux Enterprise High Availability Extension' (SLE HA). Эта подписка предоставляет доступ к необходимым пакетам и обновлениям для Keepalived и других компонентов высокой доступности. После получения подписки вы можете включить соответствующие репозитории и приступить к установке Keepalived, как указано в этом руководстве:

    SUSEConnect -p sle-ha/16/x86_64 -r ADDITIONAL_REGCODE

    Где ADDITIONAL_REGCODE — это регистрационный код, предоставленный с вашей подпиской 'SUSE Linux Enterprise High Availability Extension'.

    Настройка keepalived

    На всех серверах, которые будут размещать фронтенд Zabbix, необходимо установить Keepalived. Как упоминалось ранее, это можно сделать на отдельных серверах для разделения ролей сервера и фронтенда, но в этом руководстве мы установим Keepalived на обоих серверах Zabbix, чтобы обеспечить высокую доступность как фронтенда, так и сервера.

    Установка keepalived

    Red Hat 

    dnf install keepalived

    SUSE 

    zypper install keepalived

    Ubuntu 

    sudo apt install keepalived

    Далее нам нужно изменить конфигурацию Keepalived на всех серверах. Хотя конфигурации будут схожими, каждый сервер требует небольших изменений. Мы начнем с первого сервера. Для редактирования файла конфигурации Keepalived используйте следующую команду:

    Редактирование конфигурации keepalived

    sudo vi /etc/keepalived/keepalived.conf

    Если файл содержит существующий контент, его следует очистить и заменить следующими строками:

    vrrp_track_process track_nginx {
    process nginx
    weight 10
}

vrrp_instance VI_1 {
    state MASTER
    interface enp0s1
    virtual_router_id 51
    priority 244
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 12345
    }
    virtual_ipaddress {
        xxx.xxx.xxx.xxx
    }
    track_process {
         track_nginx
      }
}
    Warning

    Замените enp0s1 на имя интерфейса вашего устройства и замените password безопасным значением. Для virtual_ipaddress используйте свободный IP-адрес из вашей сети. Это будет использоваться как наш VIP.Мы можем теперь выполнить ту же модификацию на нашем втором или любом последующем сервере Zabbix.

    Удалите всё в файле /etc/keepalived/keepalived.conf, как это было сделано ранее, и замените его следующими строками:

    vrrp_track_process track_nginx {
      process nginx
      weight 10
}

vrrp_instance VI_1 {
    state BACKUP
    interface enp0s1
    virtual_router_id 51
    priority 243
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 12345
    }
    virtual_ipaddress {
       xxx.xxx.xxx.xxx
    }
    track_process {
         track_nginx
      }
}

    Так же, как с нашим первым сервером Zabbix, замените enp0s1 на имя интерфейса вашего компьютера и замените password вашим паролем. Заполните virtual_ipaddress так же, как это было сделано ранее.

    Убедитесь, что брандмауэр разрешает трафик Keepalived на всех серверах. Протокол VRRP отличается от стандартного IP-протокола и использует мультикаст адрес 224.0.0.18. Поэтому нам нужно явно разрешить этот трафик через брандмауэр. Выполните следующие команды на всех серверах:

    Разрешение трафика Keepalived через брандмауэр

    Red Hat / SUSE 

    firewall-cmd --add-rich-rule='rule protocol value="vrrp" accept' --permanent
firewall-cmd --reload

    Ubuntu 

    sudo ufw allow to 224.0.0.18 comment ‘keepalived multicast’

    Это завершает настройку Keepalived. Теперь мы можем продолжить адаптацию фронтенда.

    Установка и конфигурация фронтенда

    Установите фронтенд Zabbix на всех серверах Zabbix, являющихся частью кластера, следуя инструкциям из раздела Установка фронтенда.

    Warning

    Пользователи Ubuntu должны использовать VIP при установке Nginx вместе с локальным IP в директиве listen конфигурации.

    Note

    Не забудьте настроить оба фронтенда. Это новая установка, поэтому имейте в виду, что для существующих установок нам нужно закомментировать строки $ZBX_SERVER и $ZBX_SERVER_PORT в файле /etc/zabbix/web/zabbix.conf.php. Наш фронтенд будет проверять, какой узел активен, прочитав таблицу узлов в базе данных.

    Вы можете проверить, какой узел активен, запросив таблицу ha_node в базе данных Zabbix. Эта таблица содержит информацию обо всех узлах в кластере HA, включая их статус. Для проверки состояния узлов вы можете выполнить следующий SQL-запрос:

    select * from ha_node;
    Проверка таблицы ha_node в базе данных PostgreSQL 
    zabbix=> select * from ha_node;
         ha_nodeid         |  name   |   address       | port  | lastaccess | status |       ha_sessionid
---------------------------+---------+-----------------+-------+------------+--------+---------------------------
 cm8agwr2b0001h6kzzsv19ng6 | zabbix1 | xxx.xxx.xxx.xxx | 10051 | 1742133911 |      0 | cm8apvb0c0000jkkzx1ojuhst
 cm8agyv830001ell0m2nq5o6n | zabbix2 | localhost       | 10051 | 1742133911 |      3 | cm8ap7b8u0000jil0845p0w51
(2 rows)

    В этом случае узел zabbix2 определен как активный, что указывает на его статус 3, обозначающий активное состояние. Возможные значения состояния следующие:

    • 0 – Несколько узлов могут оставаться в режиме ожидания.
    • 1 – Узел, ранее обнаруженный, был отключен.
    • 2 – Узел был ранее обнаружен, но стал недоступен без правильного завершения работы.
    • 3 – Узел в настоящее время активен.

    Эта классификация позволяет эффективно мониторить и управлять состоянием внутри кластера.

    После установки фронтенда на всех серверах нам нужно запустить и включить службу Keepalived, чтобы она автоматически начинала работу при загрузке системы и начала управление VIP:

    Запуск и активация keepalived

    sudo systemctl enable keepalived nginx --now

    Проверка правильной работы

    Чтобы проверить, что установка работает правильно, подключитесь к вашему серверу Zabbix с помощью Виртуального IP (VIP). Перейдите в Reports | System Information в меню. На нижней части страницы вы должны увидеть список серверов, по крайней мере один из которых будет помечен как активный. Количество отображаемых серверов зависит от общего количества, настроенного в вашей конфигурации HA.

    1.11 проверка HA

    Выключите или перезагрузите сервер с активным фронтенда и убедитесь, что фронтенд Zabbix остается доступным. При обновлении страницы вы заметите, что другой фронтенд стал активной инстанцией, обеспечивая почти бесшовный переход и высокую доступность.

    1.12 проверка HA

    Кроме мониторинга состояния узлов HA, Zabbix предоставляет несколько команд для управления настроек failover и динамического удаления неактивных узлов.

    Одной из таких команд является:

    zabbix_server -R ha_set_failover_delay=10m

    Эта команда изменяет задержку failover, которая определяет, сколько времени Zabbix ждет перед тем как превратить стоящий узел в активный. Задержка может быть установлена в диапазоне от 10 секунд до 15 минут.

    Чтобы удалить узел, который либо остановлен, либо недостижим, следует использовать следующую команду:

    sudo zabbix_server -R ha_remove_node=`zabbix1`

    Выполнение этой команды удаляет узел из кластера HA. При успешном удалении вывод подтверждает действие:

    Удаление узла

    localhost:~ # zabbix_server -R ha_remove_node=`zabbix1`
Removed node "zabbix1" with ID "cm8agwr2b0001h6kzzsv19ng6"

    Если удаленный узел снова становится доступным, он может быть автоматически добавлен обратно при переподключении к кластеру. Эти команды для управления обеспечивают гибкость в управлении высокой доступностью Zabbix без необходимости полного перезапуска процесса zabbix_server.

    Заключение

    В этом разделе мы успешно настроили среду с высоким уровнем доступности (HA) для Zabbix, конфигурируя как серверы Zabbix, так и фронтенды для избыточности. Сначала мы установили HA для сервера Zabbix, обеспечивая, что мониторинговые службы остаются доступными даже в случае сбоя. Затем мы сосредоточились на фронтенде, внедряя Виртуальный IP (VIP) с помощью Keepalived для обеспечения бесшовного failover и непрерывной доступности.

    Кроме того, мы настроили брандмауэр для разрешения трафика Keepalived и убедились, что служба автоматически запускается после перезагрузки. С этой установкой фронтенд Zabbix может динамически переключаться между серверами, минимизируя время простоя и повышая надежность.

    Хотя высокий уровень доступности базы данных является важным аспектом, он выходит за рамки данной настройки. Однако эта основа предоставляет прочную отправную точку для построения мониторинговой инфраструктуры, которая может быть дополнена по мере необходимости.
